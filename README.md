# STM32-Balance-Car

本项目是基于 **STM32 单片机** 的两轮自平衡小车控制工程。  
系统通过姿态传感器获取车体倾角与角速度，通过编码器获取车轮速度，再利用 **角度环、速度环、转向环三套 PID 控制器** 实现：

1. 小车直立自平衡；
2. 速度闭环控制；
3. 遥控前进、后退与转向；
4. 蓝牙串口在线修改 PID 参数；
5. 根据手机摇杆输入动态设置速度目标与转向目标。

---

## 项目简介

两轮自平衡小车本质上是一个 **倒立摆控制系统**。  
其自然状态是不稳定的：车身一旦前倾或后仰，若不及时驱动车轮向倾倒方向运动，小车就会摔倒。

本项目通过以下闭环控制策略维持平衡：

- **角度环**：根据车身倾角和角速度输出主要平衡力矩；
- **速度环**：根据编码器反馈调节小车前后移动速度；
- **转向环**：根据遥控输入控制左右轮差速，实现转向；
- **输出合成**：将三个控制环的输出叠加，分别分配到左右电机。

---

## 项目整体框架

系统整体可分为以下模块：

1. `main.c`
   - 完成系统初始化；
   - 完成各外设初始化；
   - 在主循环中周期性执行控制任务。

2. 姿态检测模块
   - 读取 MPU6050 数据；
   - 获取角度与角速度；
   - 为角度环提供反馈量。

3. 编码器测速模块
   - 读取左右轮编码器计数；
   - 计算左右轮瞬时速度；
   - 为速度环提供反馈量。

4. PID 控制模块
   - 角度环 PID；
   - 速度环 PID；
   - 转向环 PID；
   - 输出限幅、积分限幅、死区补偿。

5. 电机驱动模块
   - 接收左右轮目标输出；
   - 根据输出符号控制正反转；
   - 根据输出绝对值设置 PWM 占空比。

6. 蓝牙串口模块
   - 接收手机 App 指令；
   - 接收摇杆速度和转向数据；
   - 支持在线调节 PID 参数；
   - 可选择发送实时数据用于观察波形。

7. 按键模块
   - 周期性扫描按键；
   - 识别按下事件；
   - 用于切换运行状态或触发调试逻辑。

---

## 系统控制总体逻辑

整个小车控制过程可以概括为：

1. MPU6050 获取小车当前倾角与角速度；
2. 编码器读取左右电机速度；
3. 蓝牙模块读取手机端设定的速度目标和转向目标；
4. 角度环根据姿态误差产生基础平衡输出；
5. 速度环根据速度误差产生角度补偿量；
6. 转向环根据转向误差产生左右轮差速修正；
7. 将各控制量合成为左右轮 PWM 输出；
8. 电机带动车轮运动，使小车恢复平衡并完成遥控动作。

---

## 姿态采集模块

### MPU6050简介

MPU6050 是一种常见的六轴惯性传感器，内部包含：

- 三轴加速度计；
- 三轴陀螺仪；
- 数字运动处理能力。

在平衡小车中，主要使用：

- **俯仰角**：描述车体前后倾斜程度；
- **角速度**：描述车体前后倾倒变化的快慢。

---

### 姿态角与角速度的作用

平衡车保持直立，需要同时关注：

1. **当前偏离平衡点多少**
   - 由角度反映；
   - 例如小车前倾 5°。

2. **倾倒变化有多快**
   - 由角速度反映；
   - 例如正在快速向前倒。

因此角度环通常具有类似 PD 控制特征：

```c
平衡输出 ≈ Kp × 角度误差 + Kd × 角速度
````

其中：

* `Kp` 决定小车对倾斜角度的纠正力度；
* `Kd` 决定小车对倾倒速度的抑制能力。

---

### MPU6050在平衡车中的工作流程

1. 初始化 MPU6050；
2. 读取陀螺仪与加速度计数据；
3. 通过姿态解算或滤波得到车身俯仰角；
4. 获取俯仰方向角速度；
5. 将姿态角和角速度送入角度环。

---

## 电机驱动模块

### 电机驱动基本原理

每个电机都需要两个层面的控制：

1. **方向控制**

   * 控制电机正转或反转；

2. **速度控制**

   * 通过 PWM 控制电机平均电压，从而改变转速。

---

### PWM调速原理

PWM 的本质是控制一个周期内高电平所占的比例。

* 占空比越大，电机平均电压越高；
* 电机转速通常越快；
* 占空比越小，电机输出越弱。

若控制输出为：

```c
Motor_Output = 60;
```

则表示按照一定比例向前驱动。

若控制输出为：

```c
Motor_Output = -60;
```

则表示向反方向驱动。

---

### 左右轮输出合成逻辑

平衡车最终需要分别得到左右两个电机的输出：

```c
左轮输出 = 平衡输出 + 转向修正
右轮输出 = 平衡输出 - 转向修正
```

在本工程中，若还包含速度环对角度环目标的修正，则整体思想可写为：

```c
角度目标 = 基础平衡角 + 速度环输出
平衡输出 = 角度环PID(角度目标, 实际角度)
转向修正 = 转向环PID(目标转向, 实际转向)
```

最终：

```c
LeftMotor  = 平衡输出 + 转向修正;
RightMotor = 平衡输出 - 转向修正;
```

含义如下：

* 当不转向时：

  * 左右轮输出相同；
  * 小车直线前进或后退。

* 当向左转时：

  * 左右轮输出形成差值；
  * 小车依靠差速实现转向。

---

## 编码器测速模块

### 编码器的作用

编码器用于检测电机转速和运动方向。

其主要功能：

1. 测量左轮速度；
2. 测量右轮速度；
3. 反映小车是否在前进、后退或静止；
4. 为速度环闭环控制提供反馈。

---

### 编码器速度计算逻辑

在固定采样周期内读取编码器计数变化量：

```c
速度 = 本周期计数增量
```

若：

* 计数为正，表示某一方向旋转；
* 计数为负，表示反方向旋转；
* 计数接近 0，表示车轮基本停止。

通常可进一步取左右轮平均值作为小车整体速度：

```c
实际速度 = (左轮速度 + 右轮速度) / 2
```

---

### 编码器数据在速度环中的作用

速度环的目标是使实际速度接近期望速度：

```c
速度误差 = 目标速度 - 实际速度
```

速度环输出并不直接作为电机最终 PWM，而通常作为：

* 平衡角度目标的偏置量；
* 或者作为角度环的补偿输入。

也就是说：

```c
速度环输出 -> 修正角度环Target
```

例如：

* 用户希望小车前进；
* 速度环会让角度目标略微向前倾；
* 小车为了追踪这个倾角，会主动驱动车轮向前运动；
* 从而实现前进。

---

## 三环PID控制系统

### 控制任务分解

平衡车控制可以拆解为三个问题：

1. **不倒**

   * 角度环负责。

2. **按期望速度前进或后退**

   * 速度环负责。

3. **按期望方向转弯**

   * 转向环负责。

---

### 角度环

角度环是整个系统中最核心、优先级最高的控制环。

#### 输入

* 目标角度 `AnglePID.Target`
* 当前角度 `AnglePID.Actual`
* 当前角速度，常用于微分项或独立参与平衡控制

#### 输出

* `AnglePID.Out`
* 用于生成基础平衡力矩

#### 作用

当车体前倾时：

* 电机向前加速；
* 车轮移动到车体重心下方；
* 小车恢复平衡。

当车体后仰时：

* 电机向后加速；
* 车轮向后补位；
* 小车重新立住。

---

### 速度环

速度环用于控制小车的平移速度。

#### 输入

* 目标速度 `SpeedPID.Target`
* 实际速度 `SpeedPID.Actual`

#### 输出

* `SpeedPID.Out`

#### 作用

速度环输出通常会叠加到角度目标中：

```c
AnglePID.Target = 平衡角基准值 + SpeedPID.Out;
```

含义：

* 想前进，就给出一个向前倾的目标角度；
* 想后退，就给出一个向后倾的目标角度；
* 想停止，就让目标角度回归平衡点。

---

### 转向环

转向环控制左右轮的差速，实现小车转弯。

#### 输入

* 目标转向量；
* 实际转向反馈，或者直接使用目标转向进行开环差速修正。

#### 输出

* `TurnPID.Out`

#### 作用

转向环输出一正一负作用于左右轮：

```c
LeftMotor  += TurnPID.Out;
RightMotor -= TurnPID.Out;
```

效果：

* 左右轮速度不同；
* 车体绕竖直轴转动；
* 实现左转或右转。

---

### 三环协同控制过程

三环并非彼此孤立，而是分层协同：

1. 速度环先决定小车要“向前倾多少”；
2. 角度环根据这个角度目标控制车体直立；
3. 转向环对左右轮施加差速修正；
4. 最终输出给左右电机。

可以理解为：

```text
速度环：决定“想往哪边走”
角度环：保证“走的时候不倒”
转向环：决定“往左还是往右偏”
```

---

### 左右轮最终输出计算

若定义：

* `BalanceOut = AnglePID.Out`
* `TurnOut = TurnPID.Out`

则：

```c
LeftMotor_Output  = BalanceOut + TurnOut;
RightMotor_Output = BalanceOut - TurnOut;
```

若程序中对速度环采用“修正角度目标”的方式，则速度环已经提前进入角度环逻辑，因此最终电机输出中不一定直接单独出现 `SpeedPID.Out`。

---

## PID结构体与核心参数说明

### PID结构体中的主要变量

工程中的 PID 结构体通常包含如下字段：

```c
typedef struct
{
    float Kp;
    float Ki;
    float Kd;

    float Target;
    float Actual;
    float Actual1;

    float Out;

    float Error0;
    float Error1;
    float ErrorInt;

    float OutMax;
    float OutMin;

    float OutOffset;

    float ErrorIntMax;
    float ErrorIntMin;
} PID_t;
```

---

### OutMax与OutMin

```c
.OutMax = 100,
.OutMin = -100,
```

作用：

* 限制 PID 输出最大值与最小值；
* 防止输出过大导致电机饱和；
* 避免控制量突变过猛，引起剧烈震荡。

若设置过大：

* 电机会被过强驱动；
* 小车容易剧烈冲击；
* 可能出现大幅往返摆动。

若设置过小：

* 电机纠偏能力不足；
* 小车来不及扶正；
* 容易直接倒下。

---

### OutOffset

```c
.OutOffset = 3,
```

作用：

* 用于补偿电机死区；
* 当 PID 输出很小时，若直接给 PWM，电机可能不转；
* 因此人为增加一个固定偏置，使输出一旦需要动作，就能跨过启动死区。

可理解为：

```text
理论输出很小，但电机存在静摩擦和起转门槛；
OutOffset 用于帮助电机“迈过第一步”。
```

若设置过大：

* 小车在轻微误差下也会被强行驱动；
* 容易出现原地抖动、来回晃动；
* 静止状态不够稳定。

若设置过小：

* 电机无法及时响应小误差；
* 控制系统出现“有误差但不动作”；
* 容易导致平衡延迟。

---

### ErrorIntMax与ErrorIntMin

```c
.ErrorIntMax = 600,
.ErrorIntMin = -600,
```

作用：

* 限制积分项累积范围；
* 防止积分饱和；
* 避免长时间误差累积后，PID 输出突然变得过大。

若积分限幅过大：

* 误差积累过多；
* 松手或目标改变后，小车仍然“带着历史误差继续冲”；
* 容易出现停不下来、反复前后摆动。

若积分限幅过小：

* 积分修正能力不足；
* 难以消除长期稳态误差；
* 某些负载偏差和机械偏置难以补偿。

---

## PID参数调试思路

### 角度环参数调试

角度环优先级最高，应最先调好。

#### 1. 确定平衡中值

找到小车机械直立时的角度，作为平衡参考点：

```c
机械中值 = Angle_Zero
```

角度误差通常为：

```c
Error = Target - Actual
```

---

#### 2. 调整 Kp

`Kp` 决定纠偏力度。

* 太小：

  * 小车反应迟钝；
  * 扶不住；
  * 容易缓慢倒下。

* 太大：

  * 小车过度纠正；
  * 前后剧烈来回摆；
  * 产生低频震荡。

---

#### 3. 调整 Kd

`Kd` 用于抑制倾倒速度。

* 太小：

  * 小车收不住；
  * 容易过冲。

* 太大：

  * 系统对角速度过度敏感；
  * 输出发硬；
  * 可能出现高频抖动。

---

#### 4. 是否加入 Ki

角度环一般不应过分依赖积分项。

若 `Ki` 过大：

* 容易导致小车原地来回晃；
* 控制出现滞后；
* 对姿态变化不够干脆。

但在实际机械偏置明显时，适当小积分可减小静态残余误差。

---

### 速度环参数调试

速度环用于让小车按目标速度运动，并在松手后尽量回到停止状态。

#### Kp作用

* 增强对速度误差的响应；
* Kp 过大时，可能出现速度来回修正；
* 表现为小车想停却前后反复晃。

#### Ki作用

* 消除持续速度偏差；
* 对实现“最终停住”有帮助；
* 但过大时会形成明显积分滞后。

当前工程中，若：

```c
Ki = 0.25
```

时静止状态摆动幅度更小，说明该参数在当前机械状态下对速度残余误差有一定补偿作用。

但如果摇杆松手后小车仍不立即停下，甚至来回摆动，通常可能与以下因素有关：

1. 速度环积分残留；
2. `ErrorIntMax / ErrorIntMin` 过大；
3. 速度目标恢复到 0 后，积分没有及时释放；
4. 速度环输出变化太慢；
5. 外部摇杆输入回零逻辑不够及时。

---

### 转向环参数调试

转向环用于控制差速。

#### Kp作用

* 决定转向响应快慢；
* 太小：转向迟钝；
* 太大：转向过猛，甚至影响平衡。

#### Ki作用

* 一般不宜过大；
* 若用于修正长时间左右轮差异，应谨慎设置。

#### Kd作用

* 在快速转向与回正过程中抑制突变；
* 工程中若转向需求不复杂，可先从 `Kd = 0` 开始。

---

### 常见现象与可能原因

#### 1. 小车一上电就迅速冲出

可能原因：

* 角度方向符号反了；
* 电机正反转方向与角度误差逻辑不一致；
* 角度环 Kp 极性错误。

---

#### 2. 小车能立住，但高频抖动明显

可能原因：

* Kd 偏大；
* 传感器噪声较大；
* 电机输出死区补偿过强；
* 控制周期不稳定。

---

#### 3. 小车前后慢速大幅摆动

可能原因：

* 角度环 Kp 偏大；
* 速度环 Ki 偏大；
* 积分限幅过宽；
* 控制响应存在明显滞后。

---

#### 4. 摇杆松手后，小车不能马上停下

可能原因：

* 速度目标虽已归零，但积分项仍未消除；
* `SpeedPID.ErrorInt` 保留了历史误差；
* `Ki` 较大或积分限幅较大；
* 速度环输出回落太慢；
* 输入指令归零不够及时。

---

#### 5. 小车静止时原地小幅来回摆动

可能原因：

* 速度环积分太弱，不能抵消微小偏差；
* 或积分太强，反复过补偿；
* `OutOffset` 设置不合理；
* 编码器低速测速噪声导致速度误判。

## 按键模块

### 按键扫描逻辑

按键模块采用周期轮询方式检测状态变化。

典型思路：

1. 周期性读取当前按键状态；
2. 保存上一次状态；
3. 比较前后状态；
4. 识别“按下沿”事件；
5. 将对应键值写入全局变量，供主程序处理。

---

### Key_Tick函数说明

```c
void Key_Tick(void)
{
    static uint8_t Count;
    static uint8_t CurrState, PrevState;
    
    Count ++;
    if (Count >= 20)
    {
        Count = 0;
        
        PrevState = CurrState;
        CurrState = Key_GetState();
        
        if (CurrState == 0 && PrevState != 0)
        {
            Key_Num = PrevState;
        }
    }
}
```

该函数主要实现：

1. **分频扫描**

   * `Count >= 20` 后才扫描一次；
   * 避免每次主循环都读取按键。

2. **状态记录**

   * `PrevState` 表示上一次按键状态；
   * `CurrState` 表示本次按键状态。

3. **按下事件识别**

   * 当前状态为 0；
   * 上一状态非 0；
   * 说明刚刚完成一次按键触发。

4. **键值保存**

   * 将上一次有效键值保存到 `Key_Num`；
   * 供主程序读取并响应。

## 项目控制流程总结

整个工程的核心控制链路如下：

```text
MPU6050姿态数据
        ↓
角度环PID
        ↓
基础平衡输出
        ↓
                        ┌──────────────┐
编码器速度 → 速度环PID → 修正角度目标 │
                        └──────────────┘

手机摇杆横向输入 → 转向环PID → 转向修正

最终：
左轮输出 = 平衡输出 + 转向修正
右轮输出 = 平衡输出 - 转向修正

电机执行 → 小车姿态改变 → 传感器再次反馈
```

这是一个典型的闭环控制系统：

* 传感器提供状态反馈；
* PID 根据误差计算修正量；
* 电机执行控制命令；
* 系统不断重复反馈与修正。
